  Known gap: SO exports embed the meaningful image label in the URL title attribute (![alt](url "title")), not the alt-text.
   The parser reads alt-text only. For this corpus, alt-text is uniformly "enter image description here" — so classification
   falls back to body-context rules. Impact is near-zero since these images (e.g., WhatsApp chat screenshots) have no local 
  PNG file and OCR is skipped regardless.

  11. Chunk Quality Analysis

  The KnowledgeChunker produces structure-aware chunks at 1,200 tokens / 150 overlap. Sample trace for a representative     
  article:

  Input: Q "OTP not received" → accepted answer with code example + 2 comments
  Expected output:
  - Chunk 1 (ISSUE_HEADER): question title + tags — short, classification signal
  - Chunk 2 (QUERY_BODY): question body with context + slot extraction hints
  - Chunk 3 (RESOLUTION_RCA): accepted answer prose with root cause
  - Chunk 4 (CODE_SAMPLE): code block extracted as separate chunk (if present)

  Code blocks (\``...```) are preserved in chunk content — correct for technical Q&A where code is primary evidence. Each   
  chunk carries knowledge_class, quality_score, tags_raw, and image_metadata` from the parent article.
